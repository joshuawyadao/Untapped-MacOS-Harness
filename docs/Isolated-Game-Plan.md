# Plan

Use a dedicated standard macOS test account, fresh local game data, and the game's built-in no-Steam path to test one native reward screen while preserving the normal account's progress.

## Scope
- In: A reviewed isolation plan for the installed game version, an unmodified disposable game copy and verified prepared companion copy, both apps in the same test account and graphical session, offline confinement, and one process-memory reward comparison.
- Out: Creating the account or launching the game during this planning pass; copying real saves or companion profiles; changing normal Steam settings; game signing/entitlement changes; imported progress, run history, authenticated advice, statistics, or Cloud testing.

## Action items
- [x] Verify the prerequisite: copy05 reaches `CORE_INITIALIZED_LOGGED` after manual Terms acceptance, without anonymous-token acquisition. Its protected 45-second run ended cleanly; game detection and reward reading remain untested.
- [x] Inspect the installed distribution read-only. Version `v0.107.1`, commit `59260271`, supports `--force-steam=off --nomods` before any `--` separator. The first flag skips Steam initialization; the second skips mods. No game-specific save-root override was found. The apparent `save_dir=` string is a diagnostic, not an option. These flags have not been runtime-tested here; see the [static evidence](Verification.md#isolated-game-planning-evidence).
- [ ] Obtain execution approval for a dedicated **standard local macOS account**, then have the owner create it through Users & Groups and log into its graphical session. Keep it free of Apple/Steam sign-ins and imported data. This supplies a separate actual home and Godot user-data location without relying on an unverified save flag. Account creation may require the owner's administrator password; the agent must not invoke or answer that prompt. [Apple account setup](https://support.apple.com/en-ph/guide/mac-help/mh15191/mac), [Godot data paths](https://docs.godotengine.org/en/4.5/tutorials/io/data_paths.html).
- [ ] Prepare test-account-owned disposable copies of the installed game and the verified signed copy05, plus the original harness sources and static manifests/receipt. Preserve hashes, game owner name, signatures, and entitlements. Start with empty settings, save, cache, and log directories; do not transfer existing private profiles or Terms state. Require the owner to close normal STS2 and Steam before testing; abort if either is still running rather than terminating them automatically.
- [ ] Implement and review a bounded game launcher before executing it. Use `--force-steam=off --nomods`, no inherited Steam credentials/environment, blocked remote networking, denied original-home/installed-library access, and writes confined to the disposable test account and its private session. Keep the companion's existing strict private-session policy. Add a target-PID guard that rejects any unexpected process before reader connection; preflight window counting alone is insufficient. Add synthetic command, path, signature, target-selection, and timeout tests in a focused game-launch test module, then run `python3 -m unittest discover -s tests -v`. Smoke-test the OS policy with dummy files and sockets before launching the game. Any companion ASAR change needs its own prepared signing proposal. The game flags alone do not prove save or Cloud isolation: Steam can sync independently and its restart API can launch the installed game. [Valve Cloud behavior](https://partner.steamgames.com/doc/features/cloud?l=english), [Valve restart behavior](https://partner.steamgames.com/doc/sdk/api%20?l=english).
- [ ] Obtain approval for the exact first game-launch command/policy and a 60-second first-boot probe. Verify the actual PID, executable path, user, reported data root, fresh local progression, Steam-not-initialized state, absent Steam processes, and cleanup before any gameplay. Check only the disposable data. Stop on original-data access, a Steam relaunch/login, permission prompt, migration/import attempt, or unexpected persistence. No game-signing or debugger change follows automatically from a failure.
- [ ] After isolation passes, agree a bounded manual-play session (proposed maximum 15 minutes), let the owner reach one card-reward screen, then run the copied companion for an approved 45-second observation. The owner accepts Terms manually in its fresh profile. Require exactly one game instance and independently verify its PID/path before attachment; the existing window matcher is not a path pin. Keep companion save/history lookup empty: reward IDs, upgrades, and normalized geometry come from memory. Record detection, connection acknowledgement, traversal/reward comparison, and visual overlay behavior separately; stop for a specific proposal if attachment fails.
- [ ] Shut down only supervised test processes, confirm none remain, and retain reviewed diagnostic summaries outside Git. Review the private expected-card JSON and captured reward through `compare-reward`; do not claim overlay/advice success from that comparison. Let the owner decide when to remove the test account and disposable copies. If confinement and absence of unexpected access are verified, normal saves/Cloud state should require no restore. If unexpected access occurs, stop and preserve evidence for a separately reviewed recovery plan; do not overwrite normal data or resolve Cloud conflicts automatically.
